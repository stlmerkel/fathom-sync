# fathom-sync System Patterns

Reusable patterns from shipped features. Cross-project patterns also live in mnemosyne `50-DEVELOPMENT/_shared/lessons-learned.md`.

## Attendee linking (2026-10-20)

- **Separator-preserving line split.** *When:* editing user-owned text files that may have CRLF, LF, mixed endings or a BOM. *How:* `content.split(/(\r\n|\n|\r)/)` puts line text at even indexes and each line's own separator at odd indexes. Insert `[line, sep]` pairs at the right index and `join('')`. Untouched lines come back byte-identical. At EOF, borrow the anchor's separator so the file's trailing-newline state doesn't change (`related.ts:5,16,49-61`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Artifact-keyed idempotency.** *When:* a batch or backfill edits many files and may be interrupted or re-run. *How:* decide "already done" by checking for the output itself in the target (here, the `Related: [[Name]]` line), never by a separate processed-flag or state file. A re-run then finishes partial work and is a no-op once everything is complete (`related.ts:31-44`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Pure core with an Obsidian shell.** *When:* any Obsidian plugin feature with non-trivial rules. *How:* keep the rules in modules that never import `obsidian`, take plain data in, and return a plan or rendered text. Test them with Vitest. A thin shell reads `metadataCache`, calls the core, and writes with `vault.create`/`vault.process`. Also push failure-handling decisions into the core so they are testable too, which this feature did not do. Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **JSON.stringify as a YAML scalar escaper.** *When:* writing frontmatter values that may contain quotes, colons or `#`. *How:* `s === '' ? '' : JSON.stringify(s)`. Any JSON string is a valid double-quoted YAML scalar (`contactTemplate.ts:45-48`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Invisible-character normalisation with `\u` escapes.** *When:* comparing identifiers (emails, names) that come from CSV exports, calendar APIs or hand-edited YAML. *How:* unquote, strip a `\u`-escaped class of control, NBSP, zero-width, BOM and line/paragraph separator characters, lowercase, then validate shape. Use the same normaliser on every compare path. Write the escapes in both source and tests, never as literal characters (`normalize.ts:7-17`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Preview as apply with writes disabled.** *When:* any bulk-edit command that offers a dry run. *How:* run one code path with a `write: boolean`. Both branches compute the change with the same pure function; only the write branch persists it (`linker.ts:139-168`). Apply it to *every* step, not just one: here the create step broke the pattern (`linker.ts:213-222`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Add-on step in `finally`, with its own catch.** *When:* a secondary step must run on whatever partial results a primary operation produced, and must never fail it. *How:* collect results into an array the primary step appends to as it goes. Call the secondary step in `finally`, and give it its own try/catch that only logs and notifies (`main.ts:402-404`, `441-451`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Two-click confirmation for permanent bulk actions in a Modal.** *When:* a modal button makes an irreversible change whose size depends on what the user selected. *How:* the first click relabels the button with the exact count. A flag arms the button, toggles reset it, and a short debounce stops a double-click from confirming. Use a flag because `ButtonComponent.onClick` adds listeners rather than replacing them (`ReviewModal.ts:38-94`). Scope: cross-project. Source: `attendee-contact-linker` retrospective.
- **Name-namespace index covering the whole folder.** *When:* a plugin creates notes by display name in a folder that also holds other note types. *How:* the collision index records the lowercased basename of *every* file in the folder tree, whatever its frontmatter says, uncached files included. Typed lookups (email→contact, domain→org) sit beside it. Then a case-insensitive filesystem cannot let a new note overwrite an organization or an unindexed note (`linker.ts:31-48`). Scope: project-specific. Source: `attendee-contact-linker` retrospective.
- **Directory-first, externals-to-review planning.** *When:* turning attendee lists into CRM records, where one source is trusted (an institutional directory) and the rest is not. *How:* look up by email in this order: known contact, then planned create, then queued, then directory. A directory hit becomes an automatic create; anything else goes to the review queue. A name clash with an existing file or with another create in the same run becomes a collision for manual resolution (`planner.ts:86-150`). Scope: project-specific. Source: `attendee-contact-linker` retrospective.
